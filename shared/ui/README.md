## Check for drift

Read the artifact's files (Artifact tool, `action: "read"`, `paths: [...]`, `out_dir: <scratch>`), then compare:

```bash
cmp shared/ui/bundle.js  <scratch>/project/components/bundle.js
cmp shared/ui/bundle.css <scratch>/project/components/bundle.css
```

`tokens.css` against `tokens.json`: compare every colour token in every theme (a short script does it; there were 104 values at last check, all matching).

If the artifact is ahead (Kim or another session edited it), **copy the artifact's file into this folder**, rebuild (`node arena-palimpsest/build.js --docs`) and commit. If this folder is ahead, publish it.

## Publishing a change to the artifact

1. **Read first**, in the same step, every file you will change. The artifact is edited live (Kim added the ABC Areal font files while a publish was in progress), so never send an older copy of a file over a newer one.
2. Stage the files under one folder as `<dir>/project/<path>` and publish with `root: <dir>`, one `file_path`, and the others in `files`.
3. `index.d.ts` needs `{ "from": "...", "contentType": "text/plain" }`; `.ts` is not a served type.
4. Component files and `tokens.json` first; **`project/design-system.json` last**, re-read just before, changing only `lastChange` (it also holds the font and icon records, which are the page's, not ours).
5. If a publish is refused because someone saved meanwhile, read the named files again, redo your edit on the new copy, and publish once more. Never use `force`.
6. Do not write `api/…` cards, `tokens.css` or `manifest.json`; the page generates them.
7. Each component needs a `README.md` (first sentence is its summary) and a `preview.html` whose first line is `<!-- @dsCard group="…" height=… -->`.

Comment threads on the artifact can be activated for Claude and auto-replied to. Read them with the ArtifactComments tool. A reply may already have changed the artifact (it once resized the Block action buttons), so check for drift afterwards.

## Adding a token or component

- **Token:** add it to `tokens.json` (artifact) with a value for all four themes and a usage note, **and** to each `[data-theme]` block of `tokens.css` here. Prefer are.na's own variables where they exist (`--colors-channelPublic1` and so on); say in the usage note when a value was sampled instead.
- **Component:** add the function to `bundle.js` and its CSS to `bundle.css`, register it on `window.ArenaToolkit`, add `index.d.ts` types, a README and a preview, then publish as above. Pure logic gets a test; DOM behaviour is checked in a browser (a throwaway page that loads `tokens.css`, `bundle.css`, `bundle.js` and the preview body works well).
- Colour and contrast: Arena's own colours are not all AA. Keep them and record the ratios in the component README rather than changing them.

## Conventions

- Tokens, never raw hex, in component CSS.
- No card backgrounds (Card is unfilled by default).
- British English in any visible copy.
- Everything keyboard-operable, with a visible focus ring.
